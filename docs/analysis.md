# 문서 스캐너 분석 보고서

## 데이터와 평가

`data/personal`에 있는 사용자의 실제 스크린샷 20장을 평가 입력으로 사용한다. 파일명과 해상도는 원본을 유지하며, 합성 이미지나 자동 생성 fixture는 사용하지 않는다.

```bash
.venv/bin/python -m tools.evaluate data/personal --output outputs/personal-evaluation
```

개인 이미지에는 문서 모서리의 수동 정답 좌표가 없으므로, 평가는 문서 사각형 검출과 투시 변환 결과 생성 여부를 성공 기준으로 삼는다. 결과는 `outputs/personal-evaluation`에 이미지별 처리 단계, 히스토그램, CSV, JSON, Markdown 보고서로 저장된다.

실행 결과:

| 설정 | 성공 | 실패 | 성공률 |
|---|---:|---:|---:|
| default | 17 | 3 | 85% |
| sensitive | 16 | 4 | 80% |
| strict | 11 | 9 | 55% |

## 해석

기본 설정은 세 설정 중 가장 높은 검출률을 보였다. 민감 설정은 엣지를 더 많이 보존하지만 배경의 사각형이나 그림자도 후보가 될 수 있다. 엄격 설정은 배경 노이즈를 줄이는 대신 실제 문서의 약한 경계까지 제거할 가능성이 커졌다.

이 수치는 꼭짓점의 정답 오차나 글씨 판독성을 측정하지 않는다. 실패 이미지와 성공 이미지의 `04_contours.png`, `05_warped.png`, `06_result.png`를 함께 확인해야 오검출과 미검출 원인을 구분할 수 있다. 실제 촬영에서는 그림자, 반사, 구김, 부분 가림, 문서와 배경의 낮은 대비가 고정 Canny 임계값과 가장 큰 사각형 선택 규칙을 흔드는 주요 요인이다.

## 규칙 기반 접근의 한계

현재 파이프라인은 Gaussian blur, Canny edge detection, 면적 필터, 볼록한 4각형 근사, 가장 큰 후보 선택, perspective transform, adaptive thresholding을 순서대로 적용한다. 규칙은 빠르고 해석 가능하지만, 문서가 아닌 프레임이나 책상 모서리를 문서로 선택하거나 경계가 끊긴 문서를 놓칠 수 있다. 하나의 파라미터 조합이 모든 촬영 조건에서 최적이라고 보장할 수 없다.

향후 정량 평가를 더 엄밀하게 하려면 각 이미지의 네 문서 모서리를 사람이 표시해 `personal` manifest에 `corners`를 추가하고, 기하학적 오차 기준으로 재평가해야 한다. 현재 평가는 실제 스크린샷에서 동작하는지 확인하는 운영 지표다.
